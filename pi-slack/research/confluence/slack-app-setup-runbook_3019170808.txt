Slack App Setup and Configuration Runbook

For Program TPMs

Last Updated: February 2026

Estimated Time: 30-45 minutes

Overview

This runbook guides TPMs through setting up a Slack app with webhooks and Socket Mode for their programs. By the end, you'll have:

A Slack app with proper OAuth scopes

Incoming Webhooks for automated notifications

Socket Mode for real-time event handling

Bot credentials configured in your workspace

Prerequisites

Before starting, ensure you have:

[ ] Admin or owner permissions in your NVIDIA Slack workspace (Optional since NVIDIANs do not have admin permissions of our NVIDIA Internal Workspace, which is the most used workspace)

[ ] Access to create apps at api.slack.com

[ ] Your project or team name for naming the app

[ ] A Slack channel for your project (create one if needed)

[ ] Access to your workspace .env file

Part 1: Create the Slack App

Step 1.1: Navigate to Slack API

Go to https://api.slack.com/apps

Sign in with your NVIDIA Slack credentials

Step 1.2: Create New App

Click Create New App

Select From scratch (not from manifest)

Configure:

- App Name: {Project} Bot (e.g., Partner Models Bot)

- Workspace: Select your NVIDIA workspace

Click Create App

Step 1.3: Record Your App ID

After creation, you'll be redirected to your app's dashboard. Note the App ID from the URL:

https://api.slack.com/apps/{APP_ID}

Save this App ID - you'll need it to access your app settings later.

Part 2: Configure OAuth Scopes

OAuth scopes define what your app can do. Configure both Bot Token Scopes and User Token Scopes.

Step 2.1: Navigate to OAuth & Permissions

In the left sidebar, click OAuth & Permissions

Step 2.2: Add Bot Token Scopes

Scroll to Scopes → Bot Token Scopes and add:

Note: Read this Integrate with Slack guide and make sure the scopes you request are not part of the banned scopes.

Scope

Purpose

channels:history

Read messages in public channels the bot is in

channels:read

View basic channel information

chat:write

Post messages to channels

groups:history

Read messages in private channels the bot is in

groups:read

View basic info about private channels

im:history

Read direct messages the bot is part of

mpim:history

Read messages in group DMs

users:read

View basic user info

users:read.email

View user email addresses (for lookup)

search:read

Search messages (requires admin approval)

Optional Scopes (add if needed for your workflow):

Scope

Purpose

channels:join

Join public channels

files:read

View files shared in channels

reactions:read

View emoji reactions

reactions:write

Add emoji reactions

users.profile:read

View detailed user profiles

Step 2.3: Save Changes

Click Save Changes after adding all scopes.

Part 3: Set Up Incoming Webhooks

Webhooks allow external systems to post messages to Slack channels without the full Bot Token.

Step 3.1: Enable Webhooks

In the left sidebar, click Incoming Webhooks

Toggle Activate Incoming Webhooks to On

Step 3.2: Add Webhook to Workspace

Scroll down and click Add New Webhook to Workspace

Select the channel to post to:

- For your project: #{project}-{name} (e.g., #marketing-alerts)

Click Allow

Step 3.3: Copy Webhook URL

After authorization, you'll see your webhook URL:

https://hooks.slack.com/services/T04SYRAP3/BXXXXXXXX/xxxxxxxxxxxxxxxxxxxx

Important: Store this URL securely. It allows anyone with the URL to post to your channel.

Step 3.4: Create Webhooks for Each Channel

Repeat Step 3.2-3.3 for each channel you need webhooks for:

Channel Purpose

Suggested Channel Name

Main project channel

#{project}-main

Marketing coordination

#{project}-marketing

Alerts

#{project}-alerts

Notifications

#{project}-notifications

Step 3.5: Test Your Webhook

Run this curl command to verify (replace with your webhook URL):

curl -X POST -H 'Content-type: application/json' \
--data '{"text":"Webhook test from setup!"}' \
YOUR_WEBHOOK_URL

You should see the message appear in your Slack channel.

Part 4: Enable Socket Mode

Socket Mode provides real-time event handling via WebSockets, avoiding the need for a public HTTP endpoint.

Step 4.1: Enable Socket Mode

In the left sidebar, click Socket Mode

Toggle Enable Socket Mode to On

Step 4.2: Generate App-Level Token

When you enable Socket Mode, you'll be prompted to create an App-Level Token:

Click Generate Token

Token Name: socket-mode-token

Scopes: Add connections:write

Click Generate

Step 4.3: Save App-Level Token

Copy the token that starts with xapp-:

xapp-1-AXXXXXXXXXX-XXXXXXXXXXXXX-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

This is your SLACK_APP_TOKEN for Socket Mode.

Step 4.4: Additional App-Level Tokens (Optional)

You can create additional app-level tokens for different purposes:

Token Name

Scope

Purpose

app-configurations

app_configurations:write

Configure app settings

authorizations

authorizations:read

View app authorizations

To create additional tokens:

1. Go to Basic Information → App-Level Tokens

2. Click Generate Token and Scopes

Part 6: Configure Environment Variables

Step 6.1: Update Your .env File

Open your workspace .env file and add/update these values:

# ==============================================================================
# Slack Configuration - {Your App Name}
# ==============================================================================
# App Credentials - From: https://api.slack.com/apps/{APP_ID} → Basic Information
SLACK_CLIENT_ID=your_client_id_here
SLACK_CLIENT_SECRET=your_client_secret_here
SLACK_SIGNING_SECRET=your_signing_secret_here

# Bot Token - From: https://api.slack.com/apps/{APP_ID} → OAuth & Permissions
SLACK_BOT_TOKEN=xoxb-your-bot-token-here

# App-Level Token for Socket Mode (Real-time events)
# From: https://api.slack.com/apps/{APP_ID} → Basic Information → App-Level Tokens
SLACK_APP_TOKEN=xapp-your-app-token-here

# Bot Configuration
SLACK_BOT_NAME={Project} Bot
SLACK_BOT_ICON_EMOJI=:robot_face:
SLACK_SOCKET_MODE_ENABLED=true

# API Settings
SLACK_API_TIMEOUT=10
SLACK_RATE_LIMIT_RETRIES=3
SLACK_RATE_LIMIT_DELAY=1

# Channel ID - Get with: python scripts/get_slack_channel_ids.py
SLACK_CHANNEL_ID=CXXXXXXXXXX

# Webhook URLs - From: https://api.slack.com/apps/{APP_ID} → Incoming Webhooks
SLACK_WEBHOOK_PROJECT=https://hooks.slack.com/services/T.../B.../xxx
SLACK_WEBHOOK_MARKETING=https://hooks.slack.com/services/T.../B.../xxx

Step 6.2: Get Channel IDs

Channel IDs are needed for API calls. To find them:

Option A: From Slack UI

1. Right-click on the channel name

2. Select View channel details

3. Scroll to bottom - Channel ID is shown (e.g., C08KXXXXX)

Option B: Using the API

from slack_sdk import WebClient

client = WebClient(token="xoxb-your-bot-token")
result = client.conversations_list(types="private_channel")

for channel in result["channels"]:
print(f"{channel['name']}: {channel['id']}")

Step 6.3: Update project_config.yml

Add your Slack configuration to config/project_config.yml:

slack:
project_channel:
name: "#{project}-main"
channel_id: "CXXXXXXXXXX"
webhook: "${SLACK_WEBHOOK_PROJECT}"

marketing_channel:
name: "#{project}-marketing"
channel_id: "CYYYYYYYYYY"
webhook: "${SLACK_WEBHOOK_MARKETING}"

Troubleshooting

Issue: "invalid_auth" or "not_authed"

Cause: Bot token is invalid or expired.

Solution:

1. Go to OAuth & Permissions

2. Click Reinstall App to Workspace

3. Copy the new Bot Token

4. Update .env with the new token

Issue: "channel_not_found"

Cause: Bot is not a member of the channel.

Solution:

1. Open the channel in Slack

2. Click channel name → Integrations → Add apps

3. Search for and add your bot

Issue: "missing_scope"

Cause: Required OAuth scope not configured.

Solution:

1. Go to OAuth & Permissions → Scopes

2. Add the missing scope

3. Reinstall the app

Issue: Webhook returns "no_service"

Cause: Webhook is disabled or deleted.

Solution:

1. Go to Incoming Webhooks

2. Find the webhook for your channel

3. If missing, create a new one

Issue: Socket Mode not connecting

Cause: App-level token missing connections:write scope.

Solution:

1. Go to Basic Information → App-Level Tokens

2. Click on your token and verify connections:write scope

3. If missing, generate a new token with the scope

Issue: Rate Limited

Cause: Too many API requests.

Solution:

- The workspace is configured with automatic retries

- Check config/rate_limiting_config.yml for settings

- For burst operations, add delays between requests

Security Best Practices

Token Security

Never commit tokens to Git

- All tokens should be in .env (which is gitignored)

- Use environment variables in code

Rotate tokens regularly

- Regenerate bot tokens every 90 days

- Update .env after regeneration

Limit scope requests

- Only request scopes you actually need

- Remove unused scopes periodically

Webhook Security

Treat webhooks as secrets

- Anyone with the URL can post to your channel

- Store in .env, never in code or config files

Use one webhook per channel

- Makes it easier to revoke access if compromised

Monitor webhook usage

- Review posted messages periodically

- Revoke and regenerate if suspicious activity

Channel Access

Follow your organization's channel creation policies

- Some workspaces require approval for new channels

- Document approvals in project records

Audit channel membership

- Review who has access quarterly

- Remove access when team members leave project
