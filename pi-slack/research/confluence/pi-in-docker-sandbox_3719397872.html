🚀 Quick Start — Pi Sandbox Launcher

Run one installer for your OS. It sets up everything: sbx, login, policy, and the template.

Virtualization prerequisite (verify before installing):

# Windows (elevated PowerShell, then restart):
Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform -All

# Linux (check KVM is loaded):
lsmod | grep kvm

# macOS — no additional virtualization setup needed

macOS / Linux:

cd ~/my-project
curl -fsSL https://gitlab-master.nvidia.com/vphutane/pi-sandbox-tools/-/raw/main/sandbox/install.sh | sh

Windows (PowerShell; requires Git for Windows):

cd ~/my-project
irm https://gitlab-master.nvidia.com/vphutane/pi-sandbox-tools/-/raw/main/sandbox/install.ps1 | iex

Then launch pi on any project:

pi-sbx ~/my-project                 # launch pi sandboxed on a project
pi-sbx .                            # current directory
pi-sbx . ~/shared-libs:ro           # extra read-only workspace
pi-sbx --shell .                    # bash inside the sandbox instead of pi
pi-sbx --rebuild-template           # rebuild after pi version bumps

API key: Creating a project sandbox asks for your NVIDIA Inference API key — create one at inference.nvidia.com/key-management. Press Enter to skip and set it up later.

Reconnect to an existing sandbox:

Each project gets a persistent sandbox named pi- (~/my-project → pi-my-project). Open a shell in it and start pi there: 

sbx ls                              # list your sandboxes
sbx exec -it pi-my-project bash     # open a shell inside the sandbox

Your project is mounted at the same absolute path it has on your host, so inside that shell:

cd /Users/you/my-project            # host path, unchanged inside the sandbox
pi

Or in one command from the host:

sbx exec -it pi-my-project bash -lc 'cd /Users/you/my-project && exec pi'
Shortcut: pi-sbx . reuses the existing sandbox and cds for you — no rebuild, no re-seeding. Use raw sbx when you want a second shell alongside a running pi session.
🔌 Adding models & providers

Pi has many built-in providers — Anthropic, OpenAI, Google, NVIDIA NIM, Mistral, Groq, and more. Authenticate any of them with /login API key or subscription and their models appear in /model. Refresh built-in model catalogs with pi update --models.

🔧 Manual setup (alternative to the launcher)

Already ran the Quick Start installer? Skip this section — you're set. The steps below are what the installer automates.

Step 1: Install sbx

# macOS
brew install docker/tap/sbx

# Windows (then open a new PowerShell window)
winget install Docker.sbx

# Ubuntu 24.04+
curl -s https://get.docker.com | sudo REPO_ONLY=1 sh
sudo apt install docker-sbx

# Rocky 8.9
sudo dnf -y install dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/rocky/docker-ce.repo
sudo dnf install docker-sbx

Do not use Docker Desktop's old sandbox path — standalone sbx only.

Step 2: Log in

sbx login

A browser opens with a one-time device code; sign in with your NVIDIA email. Logging in enrolls your machine in NVIDIA's centrally managed sandbox policies.

Step 3: Initialize the network policy

sbx policy init allow-all

Choose allow-all ("Balanced") — the effective allowlist is centrally managed by NVIDIA regardless of this choice.

Step 4: Install the pi-sbx launcher

# macOS (Apple Silicon):
curl -fsSL https://gitlab-master.nvidia.com/vphutane/pi-sandbox-tools/-/raw/main/sandbox/pi-sbx \
-o /opt/homebrew/bin/pi-sbx && chmod +x /opt/homebrew/bin/pi-sbx

# Linux / Intel macOS — use ~/.local/bin or /usr/local/bin:
curl -fsSL https://gitlab-master.nvidia.com/vphutane/pi-sandbox-tools/-/raw/main/sandbox/pi-sbx \
-o ~/.local/bin/pi-sbx && chmod +x ~/.local/bin/pi-sbx

Step 5: (Optional) pre-build the template

pi-sbx --rebuild-template     # ~3 minutes; otherwise the first launch builds it

Verify your setup:

pi-sbx doctor       # ✅/❌ check of your whole setup, with fixes
pi-sbx --version    # installed launcher version
pi-sbx --update     # self-update to the latest release
⚙️ What happens under the hood 
first run:  create a sandbox → install Node 22 + pi inside
→ snapshot it as the reusable "pi-agent" template   (one-time)
every run:  create/reuse a per-project sandbox from the template
→ seed pi config → start pi in your project
  • The first invocation takes a few minutes (template bootstrap); subsequent launches are near-instant.
  • Each project gets a persistent sandbox named pi-<dirname>, reused across sessions so pi authentication and state survive.
  • Mount only the project directory (plus read-only extras). Never mount your whole home directory — the sandbox intentionally blocks credential paths.
🔑 Pi configuration and authentication

pi-sbx configures pi inside the sandbox automatically:

SettingValue
ProviderRegisters nvidia-inference (the NVIDIA Inference Gateway) alongside pi's built-in providers
Defaultsnvidia-inference / nvidia/zai-org/glm-5.2
API keyAsked once on sandbox creation — create one here. Press Enter to skip.
CredentialsNever cross the sandbox boundary. Auth lives inside the sandbox — reconnecting keeps it, deleting resets it.

If you skipped the key, pi's footer may show a fallback model until you authenticate; restart pi afterwards and GLM-5.2 becomes the default.

🌐 Network policies

Network policies are not part of the sandbox image. They are enforced at runtime by the local sandboxd daemon, which checks every outbound connection from every sandbox: 

sbx login (NVIDIA email)
→ your license belongs to NVIDIA's Docker org
→ sandboxd auto-syncs NVIDIA's org-managed governance policies
→ every sandbox gets identical rules, regardless of what is installed in it
DomainPolicyUsed for
registry.npmjs.org✅ AllowedInstalling the pi CLI via npm
nodejs.org✅ AllowedNode runtime
inference-api.nvidia.com✅ AllowedPi's model provider
deb.nodesource.com❌ DeniedNot used; the launcher avoids it
github.com❌ DeniedRequest allowlisting if pi must clone from GitHub
pi.dev❌ DeniedNot used; the launcher installs via npm instead

Last verified: 2026-07-23

Useful policy commands:

sbx policy check network <host>     # will a sandbox be able to reach this?
sbx policy ls                       # view all synced policies
sbx policy profile ls               # org profiles (developer, ml-research, …)

For new domains, submit the domain allowlist request form, then restart the sbx daemon. To pin a sandbox to a specific org profile (e.g. restricted-data), use the --profile flag on sbx create.

📋 Day-to-day commands

pi-sbx <project>                  # launch (creates or reuses pi-<dirname>)
pi-sbx --shell <project>          # bash instead of pi
sbx ls                            # list sandboxes
sbx exec -it pi-<dirname> bash    # shell into an existing pi sandbox
sbx stop pi-<dirname>             # stop a sandbox
sbx rm pi-<dirname>               # remove it (wipes pi auth/state)
sbx template ls                   # see the cached pi-agent template

🔍 Troubleshooting

Start with pi-sbx doctor — it checks the sbx CLI, login state, policy sync, and network reachability, and prints the fix for each failing item.

Anything seems off
pi-sbx doctor
Bootstrap fails installing pi
sbx policy check network registry.npmjs.org and nodejs.org; if denied, request allowlisting and restart the daemon
Pi cannot reach its model
sbx policy check network inference-api.nvidia.com
A mount path is denied
Request the path to be enabled, then restart the sbx daemon
Template is stale after a pi release
pi-sbx --rebuild-template
Launcher itself is outdated
pi-sbx --update
General sbx issues
sbx diagnose
