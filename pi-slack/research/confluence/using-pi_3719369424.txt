After pi launches (whether in Docker Sandbox or on Omnistation), use this guide to learn the harness itself: how to prompt it, steer work in progress, manage sessions, switch models, add project context, and customize the toolchain.

Pi is a minimal, aggressively extensible terminal coding harness. By default the model gets a small set of tools — read, write, edit, bash plus grep, find, and ls — and uses them to fulfill your requests. Everything else is added through skills, prompt templates, extensions, and packages.

1. The interface

From top to bottom:

Startup header — shortcuts, loaded AGENTS.md files, prompt templates, skills, extensions

Messages — your prompts, responses, tool calls/results, errors

Editor — where you type; border color indicates thinking level

Footer — cwd, session name, token/cache usage, cost, context usage, current model

Toggle detail with Ctrl+O tool output and Ctrl+T thinking blocks. /hotkeys shows every shortcut for your config; customize them in ~/.pi/agent/keybindings.json.

3. Steering the agent while it works

You don't have to wait for pi to finish:

Enter while pi is working queues a steering message — delivered after the current tool call finishes, letting you redirect mid-task, for example: "actually, skip the tests for now"

Alt+Enter queues a follow-up — delivered only after all current work completes

Escape aborts and restores queued messages; Alt+Up pulls queued messages back into the editor

4. Sessions: resume, branch, travel in time

Every session auto-saves to ~/.pi/agent/sessions/ as a JSONL tree — nothing you do is ever lost, and any point can be revisited.
bashwide1800
In-session:

Command

What it does

/tree

Navigate the whole session tree; jump to ANY previous point and continue from there — branches stay in one file. Esc twice opens it.

/fork

New session from an earlier point — pick a past user message, get a fresh session from there. Great for "let me try that prompt differently".

/clone

New session from the current point — duplicates the active branch as-is with no tree baggage.

/compact [prompt]

Summarize older context to free tokens, also happens automatically near the context limit; full history stays in the file.

/session

Session ID, message count, token usage, cost

/export [file]

Export to HTML or JSONL

/import <file>

Import and resume a JSONL session

A typical branching workflow: prompt pi, don't like the result → /tree, jump back to before that prompt, phrase it differently. Still prefer the first attempt? Jump back to that branch. Both attempts stay in the history forever.

Sandbox note: avoid /share uploads to a GitHub gist — blocked by network policy, and sessions should stay on NVIDIA infrastructure. Use /export instead.

5. Login, models & providers

Logging in

If pi asks for credentials, or you skipped the key prompt at sandbox creation:

Type /login

Select nvidia-inference from the provider list

Paste your API key, created at inference.nvidia.com/key-management

/logout removes stored credentials. Auth is stored per sandbox in ~/.pi/agent/auth.json.

Switching models & thinking

The sandbox defaults to nvidia-inference / GLM-5.2. Switch or tune at any time:

Action

How

Pick a model

/model or Ctrl+L

Cycle between models

Ctrl+P / Shift+Ctrl+P scope the list with /scoped-models

Change thinking level

Shift+Tab cycles off → minimal → low → medium → high → …

Higher thinking levels make the model reason longer before acting — useful for architecture or debugging sessions; keep it low for mechanical edits.

Adding models & providers

Pi has many built-in providers -  Anthropic, OpenAI, Google, NVIDIA NIM, Mistral, Groq, and more - authenticate any of them with /login API key or subscription and their models appear in /model. Refresh built-in model catalogs with pi update --models.

Custom providers — any endpoint speaking an OpenAI, Anthropic, or Google compatible API — are added in ~/.pi/agent/models.json. That is exactly how the sandbox gets the NVIDIA Inference Gateway:
jsonwide1800
Add more models to the models array or more providers alongside, restart pi, and select them via /model.

Sandbox note: a provider is only usable if its endpoint is allowed by the network policy — check with sbx policy check network <host> on your host. inference-api.nvidia.com is allowed.

6. Project context: AGENTS.md

Pi automatically loads AGENTS.md or CLAUDE.md from your global config, parent directories, and the project root — use these files for project conventions, build commands, and "how we do things here" instructions. Advanced: replace or append the system prompt via .pi/SYSTEM.md / APPEND_SYSTEM.md.

This is pi's core idea — the harness adapts to you:

What it is

Where it lives

On-demand instruction packages, run with /skill:name or auto-loaded by the agent

TypeScript modules adding custom tools, commands, UI, event handlers — sub-agents, plan mode, permission gates, MCP support, git checkpointing are all extensions

Themes

Color schemes, hot-reloaded

~/.pi/agent/themes/

Packages

Bundles of the above, shared via npm or git

Prompt templates need front matter with a description, and pi picks up new or changed resources only after /reload:
markdownwide1800
---
description: Review staged git changes
---
Review the output of `git diff --staged` and summarize the changes.]]>

The fastest way to customize pi is to ask pi.

It knows its own extension API and file layout, so prompts like these just work, then run /reload:

"Create a prompt file in this project for reviewing staged git changes"

"Create a blue theme for the pi terminal"

"Create a pi extension that asks for confirmation before dangerous commands like rm are run"

Safety note: pi ships with zero built-in safety guards — if you ask it to delete something, it will. In this setup, Docker Sandbox or Omnistation is the primary safety net: the worst case is contained within the sandbox/vm and the mounted workspace. For additional protection, consider adding a permission-gate extension before running high-risk automation.

Browse ready-made packages — sub-agents, to-dos, MCP support, themes — in the catalog at pi.dev → Packages, then:
bashwide1800
Sandbox notes: pi install git:github.com/... won't work because github.com is policy-blocked — prefer npm packages, or internal GitLab via pi install git:gitlab-master.nvidia.com/.... Packages run with full access inside the sandbox — review third-party code before installing; the sandbox contains the blast radius but org data mounted into the workspace is still visible to it.

Pi deliberately ships without built-in sub-agents, plan mode, permission popups, or MCP — the philosophy is that these belong in extensions/packages you choose, not in the core. Ask pi itself to build what you're missing: it can explain its own extension API and write extensions for you.
